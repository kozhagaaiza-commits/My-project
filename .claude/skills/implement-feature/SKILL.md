Ты получил спецификацию фичи или день сборки: $ARGUMENTS

Выполни пошагово:

1. **Анализ.** Прочитай спецификацию и соответствующие разделы `docs/blueprint.md` (User Stories Блока 1, таблицы Блока 2, эндпоинты Блока 3, экраны Блока 4, правила Блока 5, Edge Cases Блока 6). Определи затронутые модули и файлы. Проверь, что уже сделано (`git log`, существующие файлы), чтобы не переделывать.
2. **План.** Используй plan mode перед началом реализации: список файлов, порядок, какой субагент что делает, критерии готовности (колонка «Готово, когда» из порядка сборки или критерии приёмки US).
3. **Документация.** Для всех библиотек из стека запроси актуальную документацию через Context7 MCP (use context7) ПЕРЕД написанием любого кода.
4. **База данных.** Делегируй субагенту `database-architect` создание/обновление таблиц, функций, RLS, seed.
5. **Бэкенд.** Делегируй субагенту `backend-engineer` Route Handlers, Zod-схемы, авторизацию, бизнес-логику.
   - Всё, что касается ЮKassa (платёж, webhook, сверка, возврат) — субагенту `payments-specialist`.
   - Telegram, письма, очередь уведомлений, курсы ЦБ, cron, env, Метрика — субагенту `integrations-engineer`.
6. **Фронтенд.** Делегируй субагенту `frontend-developer` страницы и компоненты со всеми состояниями Loading/Empty/Error и responsive.
7. **Проверка.** Запусти `npx tsc --noEmit`, `npm run lint`, `npm run build`. Затем делегируй субагенту `qa-reviewer` ревью всего изменённого кода. Исправь все КРИТИЧНО и ВАЖНО (через профильных субагентов), повтори ревью, пока критичных нет.
8. **Интеграция.** Убедись, что все части работают вместе: сквозной сценарий из User Story (например, подбор → карточка → корзина → оплата) проходит без ошибок.
9. **Коммит.** Осмысленный коммит на русском или английском: что сделано (например, «День 2: подбор по авто и каталоги»).
10. **Отчёт.** Кратко опиши, что сделано, какие файлы созданы/изменены, какие критерии приёмки выполнены, что требует действий владельца (ключи, настройки в кабинетах Supabase/ЮKassa/Telegram/Vercel).

Правила:
- Чертёж — источник истины: код, SQL, схемы, тексты и коды ошибок переносятся дословно.
- Если спецификация неполная или противоречит Чертежу — задай уточняющие вопросы ПЕРЕД началом работы.
- Не выходи за рамки фичи: соседние дни сборки не реализуй.
- Функция «Опт для ателье» собирается последней и уважает флаг `FEATURE_ATELIER`.
